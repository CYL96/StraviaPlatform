# 以有界同步等待交付可查询的工具执行

`generate` 与 `StraviaRead` 的所有对外入口统一采用工具声明的同步等待窗口，未声明时默认 60 秒；快速完成保持原工具结果，窗口耗尽后以 `stravia://tool-executions/<id>` 交付仍在运行的一次平台工具执行。StraviaRead 使用单 `path` 输入查询该引用，`?wait=<非负整数秒>` 控制本次最长等待，缺省立即返回；查询只观察原执行，不创建后台查询任务或重放原调用，内部 Agent 基础工具暂不改变。

执行状态与结果持久化，引用按 Principal 隔离且不授予权限；同步窗口内调用方断开则取消，后台交接后不因原请求断开而取消，进程重启中断未完成执行且不自动重放。查询原执行失败或中断时，以成功的查询结果返回明确状态与错误，不把任务失败混为查询失败。

## 取舍与影响

- 选择自动转后台而非一律返回任务封装或新增主动异步开关，保留现有快速路径；同步窗口不是任务执行期限，转后台与查询都不重置原期限。
- 非 MCP 执行的记录与结果跟随来源请求记录保留；来源记录因过期或管理操作被清理时，取消所属本地执行、删除执行记录并阻止迟到结果发布或复活。MCP 执行沿用现有历史保留策略；执行记录清理不等于删除独立 Artifact。
- 上一项为公开工具执行引入了有意的来源清理关联：清理请求记录不再对这些执行完全无影响。但它不把 Observation 改为执行事实源，不因普通诊断写入失败取消任务，也不级联删除 Generation Chain 或不属于本次清理的历史；[ADR-0060](0060-own-interaction-observation-outside-generation-chain.md) 的其余诊断隔离原则不变。
- 与 [ADR-0028](0028-persist-hidden-history-behind-markers.md) 的隐藏历史恢复不同，公开执行引用用于主动查询状态和结果，不是 History Marker 或客户端 tool-call ID；该 ADR 对重启后不重放及其他未改动工具的规则继续有效。
- 取消本地执行不能保证已经接受请求的上游停止或不消耗额度；不能承诺恰好执行一次。同步等待窗口耗尽且后台交接持久化后即视为后台执行，不等待客户端确认收到引用，因此引用交付失败后执行仍可能继续。

本文保留 proposed 状态，不把生成规格等同于独立的最终架构确认；尚未实施。完整契约、测试 seam 与决策来源已整理为标记 `ready-for-agent` 的[本地规格](../../.scratch/async-platform-tools/spec.md)，按本次不再访谈的要求直接发布。
