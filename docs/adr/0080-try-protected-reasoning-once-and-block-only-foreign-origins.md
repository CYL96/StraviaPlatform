# 受保护推理先回放一次，被拒后只屏蔽非本上游来源

本决策取代 [ADR-0075](0075-replay-protected-reasoning-within-protocol-and-learn-rejections.md) 中“出口协议不同或协议绑定模型不同时提前剥离”“第二级剥离全部载荷”以及“按单个载荷摘要记忆拒绝”的规则。ADR-0075 的乐观回放、拒绝分类、恢复不计入 Target 失败与重试预算、拒绝记忆只存在内存等约定保持不变。

## 规则

受保护载荷指 `Thinking.signature`、Responses `Reasoning.encrypted_content` 与 `RedactedThinking.data`。宿主为每个受保护载荷确定来源：

- **本上游**：载荷由当前签发作用域（协议、部署地址、凭据身份，以及协议要求时的模型）返回。
- **外来**：载荷有来源记录，但签发作用域不是当前上游。
- **来源不明**：客户端自带、来源记录丢失，或载荷被插入到不是它签发方的条目里。

来源以载荷为单位。宿主把上游返回的条目标记为该签发作用域，并在同一私有标记中记录该作用域实际返回的载荷摘要；条目中不在摘要清单内的载荷按来源不明处理。旧记录没有摘要清单时，条目内全部载荷按旧标记的签发作用域处理。

1. **首次总是回放。** 宿主不再因出口协议不同、模型不同或签发作用域不同而在首发前剥离载荷。目标协议有对应的不透明载荷位置时，codec 原样放入；没有对应位置时，按 OMP 的做法降级：可读的 summary/content 转为普通文本，redacted 数据丢弃。这属于协议无法承载，不是来源屏蔽。
2. **被拒后只剥离非本上游载荷。** 插件把拒绝分类为 `protected-reasoning-rejected` 且尚未提交输出时，宿主剥离全部外来与来源不明的载荷，保留本上游载荷，然后重放一次。没有可剥离的非本上游载荷，或剥离后再次被拒，错误按原样返回，不再剥离本上游载荷。重放是一次新的上游请求，Target 首 token 超时从重放开始重新计时，被拒请求的耗时不占用它的窗口；总 deadline 不变。
3. **按上游对记忆拒绝。** 剥离后的重放没有再被判为推理拒绝时（包括成功、其它错误，以及在首 token 超时等取消下结束），宿主记住：当前签发作用域拒绝来自某签发作用域的载荷；来源不明的载荷仍按载荷摘要记忆。此后发往同一签发作用域的请求，在首发前直接剥离命中记忆的来源或载荷。
4. **拒绝分类需要证据。** 上游不给出专门错误码时（例如 Devin 的 Connect `invalid_argument`），插件只有在宿主声明本次请求含有非本上游载荷时，才把该错误分类为推理拒绝；否则按普通请求错误处理，避免把其它参数错误误判为载荷问题。宿主通过 `ProviderSnapshot.operation_metadata` 的 `protected_reasoning_untrusted` 声明这一事实。

拒绝记忆仍是可丢失的进程内状态：重启后清空，多实例之间不共享，不需要 schema 变更。

## Considered Options

- **保持 ADR-0075 的提前剥离。** 跨协议必然失败的场景省掉一次请求，但 Devin 等聚合上游可能接受其它协议签发的载荷，提前剥离会丢失可回放的推理链。
- **被拒后全部剥离（ADR-0075 的第二级）。** 能从本上游载荷损坏中恢复，但会屏蔽本上游返回的推理，与“只屏蔽外来来源”冲突。本上游载荷确实损坏时，错误原样返回更容易诊断。
- **持久化拒绝记忆。** 重启后省去一次被拒往返，但需要 schema 与多实例一致性处理；收益不足。

## Consequences

- 历史中带有外来载荷时，每个“当前上游 × 来源上游”组合在进程生命周期内最多多一次被拒请求，均发生在任何输出之前。
- 本上游载荷被拒时不再自动恢复，客户端会看到上游错误。
- 插件对没有专门错误码的上游，必须结合宿主的 `protected_reasoning_untrusted` 声明分类，不能单凭模糊错误码判定。
